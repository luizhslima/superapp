# ADR-012 · Mini-apps web estáticos (Next.js/Vite exportados) em webview isolada

- **Status**: Proposed (2026-11-12) — **adiado**: só entra quando houver um caso real que a UI declarativa ([ADR-009](ADR-009-miniapp-ui.md)) não cobre
- **Contexto**: o ADR-009 escolheu UI declarativa e deixou a opção (b), webview por mini-app, como evolução. A pergunta de agora é usar frameworks como Next.js. Servidor Node dentro do app (SSR, rotas de API, server components, middleware) está **descartado**: Node em execução, peso e superfície de ataque quebram o modelo do host. Resta o que roda como arquivos estáticos.
- **Gatilho para implementar** (qualquer um): gráficos ou canvas, editor de texto rico, arrastar e soltar, ou uma tela que passe repetidamente dos limites do catálogo (200 nós, 64 KiB, só componentes fixos). Sem caso real, não se constrói.
- **Decisão (quando o gatilho ocorrer)**: segundo tipo de mini-app, `kind: "web"` no manifesto, **sempre estático**.
  - **Entrega**: no v1, **um único HTML** com JS e CSS embutidos (Vite + `vite-plugin-singlefile`, ou exportação estática do Next.js processada no empacotamento). Cabe no contêiner do ADR-010 (campo de carga trocado de `wasm` para `html`, hash e assinatura iguais; limite ~8 MiB). Pacote com vários arquivos fica para uma extensão com índice explícito (sem `..`, sem diretórios, nº e tamanho máximos).
  - **Next.js, só como exportação estática** (`output: 'export'`). Não suportado: SSR, ISR, rotas de API, middleware, server actions, otimizador de imagens. Vite/React puro continua sendo a referência (mais leve que o Next para esse uso).
  - **Origem própria por app**: janela `web-<id>` criada **só pelo host** (mesmo padrão de `app-<id>`), servida por um esquema próprio (`sapp-web://<id>/`) a partir dos bytes do pacote **já verificado** em memória, nunca do disco. Origem distinta isola `localStorage`/IndexedDB entre apps.
  - **CSP rígida**: `default-src 'none'`; `script-src` e `style-src` por **hash** calculado pelo host ao servir (nada de `unsafe-inline`, `eval`, `wasm-unsafe-eval` só se o app declarar); `img-src 'self' data:`; **`connect-src 'none'`**: a página não faz `fetch`/WebSocket para lugar nenhum.
  - **Ponte única**: `window.superapp` expõe só as interfaces do host que o manifesto pediu e o usuário aprovou (`storage`, `clock`, `log`, `http` do [ADR-011](ADR-011-miniapp-network.md)), pelo Router com a identidade vinda do **rótulo da janela** (como `view.dispatch`), com política deny-by-default por prefixo. A rede do app web passa **sempre** pelo `http` mediado, com lista de domínios, limites e auditoria.
  - **Navegação travada**: sem navegação de topo, `window.open`, novas janelas, `iframe` externo, downloads nem abertura de arquivo por arrastar; sem DevTools no release. Em macOS a janela entra no mesmo agrupamento de abas.
  - **Ferramentas**: `cargo xtask new-web-app` e `build-web-app` (empacota, embute, assina), no molde do `new-app`/`build-app`.
- **Spike antes de aceitar**: medir memória e abertura de uma janela web extra (cada uma é um processo de renderização do WebView2; o S5 mediu ~150 MB privados com a janela principal) e testar a CSP por hash em WebView2, WebKitGTK e WKWebView. Resultado entra no ADR.
- **Consequências**: (+) UI rica sem abrir exceção no host; mesmo modelo de assinatura, consentimento e permissões. (−) **muda a premissa do ADR-009**: o código do app passa a executar na página (a defesa é WebView + CSP + ponte mínima, não mais "nada executa"); um tipo de app mais caro em memória; dois renderizadores para manter; novas classes de bug (XSS dentro do próprio app, escapes de CSP).
- **Alternativas descartadas**: Next.js com servidor/sidecar Node (peso, superfície, fora do modelo); iframe em `https://` remoto (código não verificado, sem assinatura); estender o catálogo declarativo sem limite (vira um HTML disfarçado e perde a garantia de validação); GPUI como renderizador de mini-apps (ver [radar](../10-radar-gpui-shell.md); outra decisão, de casca).
- **Riscos**: R6, R7. Exige fuzz do contêiner com `kind: "web"`, testes de negação da ponte (janela sem capability, app tentando falar por outro id, `connect-src`), e atualização do [modelo de segurança](../06-security-model.md) antes de liberar no catálogo.
